## 1. 제품 개요

### 1.1 비전

**함께한 순간이, 오래 남는 추억이 되도록.**

친구들과의 만남을 일회성 이벤트로 끝내지 않고, 약속부터 기록과 회상까지 이어지는 공동 추억으로 만든다.

### 1.2 제품 정의

**[제품 결정 v1]** 서비스는 공개 팔로워 기반 SNS가 아니라, 초대받은 사람만 접근할 수 있는 **약속 단위의 프라이빗 공동 추억 공간**이다.

하나의 `Memory Event(추억 이벤트)`가 다음 정보를 연결한다.

- 언제 만났는지: 날짜·시간
- 누구와 함께했는지: 참여 멤버
- 어디에 갔는지: 사용자가 선택한 장소
- 무엇을 남겼는지: 사진·짧은 영상·한 줄 메모·반응
- 어떻게 다시 찾는지: 지도·날짜·친구 기반 탐색

### 1.3 핵심 루프

```text
약속 생성
  ↓
초대 링크로 친구 참여
  ↓
모임 중/후 사진·짧은 영상 공동 추가
  ↓
장소·날짜·친구 맥락으로 추억 자동 구성
  ↓
지도 또는 타임라인에서 회상
  ↓
다음 만남을 기록할 동기 형성
```

### 1.4 목표

1. 약속과 사진 공유가 분리되어 생기는 기록 부담을 줄인다.
2. 여러 친구가 찍은 사진과 이야기를 하나의 추억으로 모은다.
3. 장소·날짜·친구 맥락을 통해 과거 기록을 쉽게 다시 찾게 한다.
4. 위치와 사진 공개에 대한 사용자의 통제권을 기본값으로 보장한다.

### 1.5 비목표

- 불특정 다수에게 콘텐츠를 노출하는 공개 SNS
- 복잡한 일정 투표·캘린더 대체 서비스
- 실시간 친구 위치 추적 서비스
- 여행 경로 자동 기록에 특화된 여행 앱
- 클라우드 사진 원본 백업 서비스
- 메신저 또는 커뮤니티 피드 대체

## 2. 문제 정의

### 2.1 핵심 문제

> 친구들과 함께한 순간은 약속, 사진, 대화, 장소 기록으로 흩어져 있어 시간이 지난 뒤 그날의 경험을 하나의 이야기로 다시 떠올리기 어렵다.

### 2.2 문제 가설

아래 내용은 모두 **[가설]**이며, 인터뷰와 프로토타입 테스트로 빈도·심각도·대안 행동을 확인해야 한다.

| 문제 가설 | 현재 사용자 행동 | 예상되는 불편 |
|---|---|---|
| 기록 분산 | 약속은 메신저, 사진은 각자 갤러리, 장소는 지도 앱에 존재 | 경험의 맥락이 끊기고 다시 찾기 어려움 |
| 기록 부담 | 모임 후 사진을 고르고 별도 앨범을 만들어야 함 | 정리를 미루거나 포기함 |
| 참여 불균형 | 일부 사람만 사진을 공유함 | 각자의 시선이 모이지 않고 사진 전달이 누락됨 |
| 장소 맥락 소실 | 사진만 남고 방문한 장소의 이름이 남지 않음 | 재방문하거나 추천할 때 장소를 찾기 어려움 |
| 회상 계기 부족 | 공유 후 대화방이나 앨범을 다시 열지 않음 | 저장된 추억이 장기적으로 활용되지 않음 |
| 공개 피로 | 공개 SNS에는 사적인 일상을 올리기 부담스러움 | 기록 자체를 하지 않거나 제한된 사진만 공유함 |

### 2.3 기회 영역

**[가설]** 이미 확정된 약속을 기록의 시작점으로 사용하면 사용자가 별도의 앨범 구조를 고민하지 않아도 되고, 날짜·참여자·장소가 자연스럽게 추억의 맥락으로 남을 것이다.

### 2.4 해결 원칙

1. **사진 한 장만으로도 기록 완료:** 메모·감정·장소는 선택 입력이다.
2. **한 명만 참여해도 기능 작동:** 공동 기여가 적어도 추억 공간은 유효하다.
3. **나중에 기록 가능:** 모임 중 앱 사용을 강요하지 않는다.
4. **위치 권한 없이도 핵심 기능 사용:** 수동 장소 선택을 기본으로 한다.
5. **비공개가 기본:** 링크 유출만으로 기록이 공개되지 않는다.
6. **회상은 맥락 중심:** 사진 수보다 누구와·언제·어디서의 연결을 우선한다.

### 3.1 1차 타깃

**[가설]** 친한 친구 2~6명과 월 1회 이상 만나고, 만남이나 여행에서 사진을 자주 찍지만 별도 정리에는 시간을 쓰고 싶지 않은 20~30대 모바일 사용자.

> 연령은 초기 리서치 모집을 위한 조건일 뿐이다. 실제 핵심 세그먼트는 나이보다 **모임 빈도, 사진 공유 빈도, 회상 욕구, 프라이버시 민감도**로 재정의해야 한다.

### 3.2 보조 타깃

- 여행·생일·공연·맛집 탐방 등 반복되는 소규모 모임을 운영하는 사람
- 사진을 많이 찍지만 친구에게 전달하는 일을 자주 미루는 사람
- 공개 SNS보다 소수와 사적으로 기록하고 싶은 사람
- 과거 방문 장소나 친구와의 기록을 다시 찾는 빈도가 높은 사람

### 3.3 비타깃

- 대규모 공개 이벤트의 참석자 관리가 주목적인 사용자
- 업무 일정이나 프로젝트 일정을 관리하려는 사용자
- 실시간 위치 공유 또는 안전 추적이 필요한 사용자
- 전문 사진가의 원본 파일 전달·보정 워크플로가 필요한 사용자

## 4. 가치 제안과 경쟁 차별화

### 4.1 가치 제안

- **Effortless Capture:** 약속에서 바로 기록하고, 사진 한 장만으로도 완료한다.
- **Shared Memory:** 친구들의 서로 다른 사진과 이야기를 한 이벤트에 모은다.
- **Meaningful Recall:** 사진을 날짜·장소·친구 맥락으로 다시 발견한다.
- **Private by Default:** 초대와 승인, 선택적 위치 공개를 기본 설계로 둔다.

### 4.2 경쟁 구도

| 범주/서비스 | 공식 자료에서 확인되는 강점 | 본 서비스가 집중할 차이 |
|---|---|---|
| Apple 사진 공유 앨범 | 참여자의 사진·영상 추가, 댓글·반응, 멤버 권한 관리 | 약속 생성부터 장소·관계 기반 회상까지 하나의 흐름으로 연결 |
| Polarsteps | 여행 경로·지도, 사진·영상·글, 공동 여행 기록 | 여행이 아닌 일상적 친구 모임까지 포괄하고 실시간/자동 경로 추적을 핵심에서 제외 |
| Partiful | 이벤트 생성·초대·RSVP, 이벤트 사진 업로드 | 참석 관리보다 모임 이후 장기 기록과 친구·장소별 회상에 초점 |
| 메신저 대화방 | 이미 형성된 관계망, 즉시 사진 전송 | 대화 흐름에 묻히지 않는 구조화된 공동 추억과 장기 탐색 제공 |

**주의:** 공동 앨범, 지도 기록, 이벤트 사진 업로드 각각은 이미 존재하는 기능이다. 따라서 이를 단독으로 독창적 기능이라고 주장하지 않는다.

### 4.3 차별화 전략

**[제품 결정 v1]** 차별화의 중심은 기능 목록이 아니라 다음 연결 구조다.

1. **약속 기반 기록:** 확정된 약속이 별도 설정 없이 공동 추억 공간이 된다.
2. **일상까지 포괄:** 여행뿐 아니라 카페, 생일, 공연, 산책도 동등한 추억 단위다.
3. **관계 기반 회상:** 장소뿐 아니라 “이 친구와 언제 무엇을 했는가”를 찾는다.
4. **비공개 기본값:** 콘텐츠·장소는 승인된 멤버에게만 보인다.
5. **부담 없는 기여:** 한 명만 기록해도 작동하고, 다른 멤버는 나중에 참여할 수 있다.

### 4.4 포지셔닝 문장

> 여행 기록 앱이 아닌, 친구들과의 반복되는 만남이 지도와 타임라인에 쌓이는 프라이빗 소셜 메모리 서비스.

### 4.5 핵심 가치 가설

**[가설]** 사용자는 “공동 사진 저장” 그 자체보다, 이미 잡힌 약속에 사진과 장소가 자연스럽게 연결되고 특정 친구와의 과거를 다시 찾을 수 있을 때 더 높은 가치를 느낄 것이다.

| F15 | 지난 약속 사진 추가 알림 | 1회성·옵트아웃 가능 | P1 | 알림 콘셉트 |
| F16 | N년 전 오늘 | 회상 카드 및 알림 | P2 | 로드맵 |
| F17 | 자동 동선 기록 | 백그라운드 위치 기반 경로 | P2 | 제외 |
| F18 | AI 하이라이트 | 사진·영상 자동 요약 | P2 | 제외 |
| F19 | 일정 투표·추천 | 후보 시간·장소 조율 | P2 | 제외 |
| F20 | 원본 일괄 내보내기 | 앨범 다운로드·백업 | P2 | 정책 방향만 정의 |

### 5.3 7일 프로젝트의 P0 컷라인

프로토타입에서 반드시 연결해야 하는 한 줄 시나리오는 다음과 같다.

> 사용자가 약속을 생성하고 친구를 초대한 뒤, 친구가 참여해 사진을 추가하고, 장소 핀이 생성되며, 두 사람이 타임라인과 지도에서 그 기록을 다시 찾는다.

짧은 영상은 제품 방향에는 포함하지만, **실제 업로드·인코딩·재생 개발은 7일 프로젝트 범위에서 제외**하고 P1 상호작용으로 시뮬레이션한다.

### 6.2 이벤트 상태

| 상태 | 조건 | 기본 UI |
|---|---|---|
| `UPCOMING` | 시작 시각 전, 취소되지 않음 | 일정·장소·멤버·기록 추가 진입점 |
| `ONGOING` | 시작~종료 사이 | 사진 추가를 가장 강하게 노출 |
| `PAST_EMPTY` | 종료 후, 유효 기록 0개 | 빈 앨범 대신 “사진 추가” 안내 |

| `CANCELLED` | 호스트가 취소 | 취소 배지, 기존 기록 처리 선택 |
| `ARCHIVED` | 모든 멤버가 보관 처리 또는 정책상 보관 | 기본 목록에서 숨김, 복원 가능 |

이벤트가 종료되었다고 별도 객체로 복사하지 않는다. 동일한 `MemoryEvent`가 상태만 바뀌어 약속에서 추억으로 전환된다.

## 7. 주요 사용자 플로우

### 7.1 첫 사용자: 약속 생성

```text
홈 → [새 약속]
→ 제목 입력(필수)
→ 날짜 입력(필수)
→ 시간·장소 입력(선택)
→ 비공개 기본값 확인
→ 생성 완료
→ 약속 상세
→ 초대 링크 공유 또는 나중에 초대
```

예외:

- 제목이 비어 있으면 생성 불가
- 과거 날짜도 생성 가능하며 즉시 `PAST_EMPTY` 또는 `MEMORY` 상태로 진입
- 장소 권한을 거부해도 수동 검색·장소 없이 생성 가능
- 친구를 초대하지 않아도 본인만의 기록 가능

### 7.2 초대받은 사용자: 참여

```text
초대 링크 열기
→ 공개 가능한 최소 정보(제목·날짜·호스트) 확인
→ 로그인/가입
→ 참여 요청
→ 호스트 승인
→ 이벤트 접근
```

**[제품 결정 v1]** 링크를 가진 사람에게 사진·정확한 장소·멤버 목록을 바로 노출하지 않는다. 로그인과 승인 전에는 최소 정보만 표시한다.

예외:

- 링크 만료: 호스트에게 새 링크 요청 안내
- 이미 참여 중: 이벤트로 바로 이동
- 차단 관계: 참여 요청 불가, 상세 사유는 노출하지 않음
- 승인 대기: 콘텐츠 접근 불가, 요청 취소 가능
- 거절: 재요청 쿨다운 **[결정 필요]**

### 7.3 공동 기록 추가

```text
이벤트 상세 → [사진/영상 추가]
→ 사진 라이브러리 권한 요청(필요 시)
→ 여러 장 선택
→ 선택 항목 미리보기
→ 장소 연결(선택)
→ 한 줄 메모·감정(선택)
→ 업로드
→ 항목별 성공/실패 표시
→ 타임라인에 즉시 반영
```

원칙:

- 메타데이터가 없어도 사진 업로드를 막지 않는다.
- 여러 파일 중 일부 실패 시 성공 파일은 유지하고 실패 파일만 재시도한다.
- EXIF 위치는 사용자 확인 없이 공개 장소로 자동 반영하지 않는다.
- 영상은 P1이며, 길이·크기 제한을 선택 화면에서 미리 알린다.

### 7.4 추억 지도 탐색

```text
추억 지도
→ 핀 또는 클러스터 선택
→ 장소명·방문 횟수·대표 사진 미리보기
→ 장소 상세
→ 해당 장소의 이벤트 목록
→ 이벤트 상세/미디어 상세
```

예외:

- 장소가 없는 기록은 지도에서 제외하되 보관함에서는 정상 노출
- 동일 장소의 여러 이벤트는 하나의 핀으로 묶고 방문 횟수 표시
- 비슷하지만 다른 장소는 장소 ID를 기준으로 구분
- 정확한 좌표 공개가 민감한 장소는 넓은 지역 단위 표시 **[P1/정책 검증 필요]**

### 7.5 타임라인 회상

```text
추억 보관함
→ 최신순 이벤트 카드
→ 친구/기간 필터(P1)
→ 이벤트 상세
→ 사진·영상·메모를 시간순 탐색
```

사용자 질문 예시:

- “우리 마지막으로 홍대에서 만난 게 언제였지?”
- “작년 지현이 생일 사진이 어디 있지?”
- “민수와 함께 부산에서 갔던 카페가 어디였지?”

### 7.6 멤버 탈퇴·기록 삭제

```text
이벤트 설정 → [이 이벤트 나가기]
→ 접근권한 상실 안내
→ 내가 올린 기록 처리 선택
   ├─ 기록을 남기고 나가기
   └─ 내가 올린 기록 삭제 후 나가기
→ 재인증/확인
→ 처리 완료
```

**[결정 필요]** “기록을 남기고 나가기”의 법적 동의 문구, 댓글·반응의 종속 삭제 범위, 백업 보존 기간은 출시 전 확정해야 한다.

## 9. 상세 기능 요구사항

### 9.1 약속 생성·수정

- 호스트는 제목·날짜·시간·예정 장소를 생성·수정할 수 있다.
- 날짜와 제목만 입력해도 생성된다.
- 변경 이력 중 날짜·장소 변경은 멤버에게 알린다 **[P1]**.
- 과거 날짜로 생성할 수 있다.
- 약속이 취소되어도 기존 기록은 자동 삭제하지 않는다.
- 호스트가 없는 이벤트는 허용하지 않는다. 호스트 탈퇴 전 역할 이전을 요구한다 **[제품 결정 v1]**.

### 9.2 초대·참여

- 초대 링크에는 추측이 어려운 토큰을 사용하고 만료·폐기할 수 있어야 한다.
- 기본 만료 기간은 7일 **[제안/검증 필요]**.
- 참여자는 로그인 후 참여 요청을 보내고 호스트 승인을 받아야 한다.
- 한 이벤트의 권장 인원은 2~6명이며 시스템 상한은 20명 **[제안/부하 검증 필요]**.
- 한 명만 있는 이벤트도 정상 동작한다.

### 9.3 미디어

- P0 지원: JPEG, PNG, HEIC 등 모바일 일반 이미지 **[기술 검증 필요]**.
- P1 지원: 일반 모바일 영상 포맷, 최대 15초 또는 100MB **[제안/비용 검증 필요]**.
- 업로드 시 서버용 파생 이미지(썸네일)를 생성하되 원본 보존 여부는 **[결정 필요]**.
- 파일 업로드 실패는 항목 단위로 복구한다.
- 동일 파일 중복 업로드는 해시·사용자 확인으로 방지 또는 경고한다 **[P1]**.
- 촬영 시각이 없거나 부정확해도 이벤트 기록 시각을 기준으로 정렬할 수 있다.

### 9.4 장소

- 장소 연결은 선택 사항이다.
- 예정 장소와 실제 기록 장소를 별도 필드로 관리한다.
- EXIF 좌표는 자동 공개하지 않고 장소 추천에만 사용할 수 있다 **[사용자 동의·법무 검토 필요]**.
- 사용자는 장소를 수정하거나 제거할 수 있다.
- 지도에는 장소가 연결된 미디어/이벤트만 나타난다.
- 실시간 위치나 친구의 현재 위치는 수집·표시하지 않는다.

### 9.5 타임라인

- 기본 정렬은 촬영 시각, 없으면 업로드 시각이다.
- 장소 없는 미디어도 표시한다.
- 삭제·신고 처리 중인 미디어는 상태에 따라 숨김 또는 블러 처리한다 **[결정 필요]**.
- 여러 사용자의 동시 업로드에도 중복 없이 최신 상태를 반영한다.

### 9.6 알림

- P0: 참여 승인/거절, 멤버 제거, 신고 결과 등 보안·권한성 알림
- P1: 친구가 기록 추가, 지난 약속 사진 추가 요청
- P2: N년 전 오늘, 월간 회상
- 마케팅·회상 알림은 기본 옵트아웃 가능해야 한다.
- 미참여자에게 반복 알림을 보내지 않는다.

## 10. 데이터 모델

### 10.1 관계 개요

```text
User 1 ── N EventMember N ── 1 MemoryEvent
MemoryEvent 1 ── N Invitation
MemoryEvent 1 ── N MemoryEntry
MemoryEntry 1 ── N MediaAsset
MemoryEntry N ── 0..1 Place
MemoryEntry 1 ── N Reaction
MemoryEvent 1 ── N AuditLog
MediaAsset 1 ── N ModerationCase
```

#### ModerationCase / AuditLog

- 신고 대상, 신고자, 사유, 증거, 처리 상태, 처리자, 처리 시각을 기록한다.
- 멤버 제거, 공개 범위 변경, 링크 재발급, 대량 삭제 등 권한성 행동을 감사 로그로 남긴다.
- 감사 로그의 보존 기간은 **[법무·보안 검토 필요]**.

### 10.3 데이터 무결성 규칙

- 활성 이벤트에는 반드시 1명의 `OWNER`가 있어야 한다.
- `ACTIVE` 멤버만 이벤트 콘텐츠를 조회·작성할 수 있다.
- `MediaAsset.uploader_user_id`는 업로드 당시 활성 멤버여야 한다.
- 장소가 삭제되어도 미디어는 삭제되지 않는다.
- 이벤트에 유효 기록이 1개 이상이면 상태는 `MEMORY`, 0개이면 종료 후 `PAST_EMPTY`다.
- 삭제 처리는 사용자 UI에서 즉시 숨기고, 백업·감사 목적의 실제 삭제 시점은 정책에 따른다.

## 11. 권한·프라이버시 정책

### 11.1 권한 매트릭스

| 행동 | 호스트 | 활성 멤버 | 비멤버/승인 대기 |
|---|:---:|:---:|:---:|
| 이벤트 상세 조회 | O | O | X |
| 제목·날짜·예정 장소 수정 | O | X | X |
| 본인 기록 추가 | O | O | X |
| 본인 기록 수정·삭제 | O | O | X |
| 타인 기록 직접 삭제 | 신고/숨김 요청만* | 신고/삭제 요청만 | X |
| 멤버 승인·제거 | O | X | X |
| 초대 링크 발급·폐기 | O | X **[P1 위임 가능]** | X |
| 이벤트 취소 | O | X | X |
| 이벤트 삭제 | O, 확인 절차 필요 | X | X |
| 이벤트 나가기 | 역할 이전 후 가능 | O | 해당 없음 |

\* 불법·위험 콘텐츠의 긴급 숨김 및 운영자 삭제 정책은 별도 운영 체계로 처리한다.

### 11.2 기본 공개 원칙

- 모든 이벤트와 기록은 `MEMBERS_ONLY`가 기본이자 P0의 유일한 공개 범위다.
- 링크 소지만으로 콘텐츠를 볼 수 없다.
- 승인 전 노출 정보는 이벤트 제목·날짜·호스트 표시명 수준으로 최소화한다.
- 장소의 정확한 좌표는 승인된 멤버에게만 보인다.
- 공개 링크, 검색 엔진 노출, 팔로워 피드는 P0에서 제공하지 않는다.

### 11.3 위치 정보

- 위치 권한은 선택이며 거부해도 서비스 이용 가능하다.
- 백그라운드 위치를 수집하지 않는다.
- 사진 EXIF 위치는 명시적 확인 없이 공유 장소로 게시하지 않는다.
- 민감 장소 보호를 위해 좌표 정밀도 완화 옵션을 P1로 검토한다.
- 사용자는 언제든 장소를 수정·제거할 수 있다.

### 11.4 사진·영상과 초상권

- 업로더는 공유 권한이 있는 콘텐츠만 업로드해야 한다는 안내에 동의한다.
- 사진에 등장하는 멤버는 삭제 요청 또는 신고를 할 수 있어야 한다.
- 앱 내 삭제가 다른 사용자가 저장·캡처한 사본까지 회수하지 못한다는 점을 명확히 안내한다.
- 미성년자, 불법 촬영물, 성적 콘텐츠, 괴롭힘 등 처리 정책은 **[법무·안전 검토 필요]**.

### 11.5 삭제·탈퇴·보존

- 본인 업로드 기록은 본인이 삭제할 수 있다.
- 멤버 제거 시 접근 토큰을 즉시 무효화한다.
- 탈퇴 사용자의 기록을 남길지 삭제할지 선택하게 하는 방향을 제안하되, 실제 처리 기준은 **[결정 필요]**.
- 삭제 요청 후 백업에서 완전히 제거되는 최대 기간은 **[결정 필요]**.
- 계정 탈퇴 전에 호스트 역할 이전과 데이터 영향 범위를 안내한다.
- 서비스 종료 시 사용자가 기록을 내보낼 수 있는 절차를 장기 정책으로 마련한다.

### 11.6 보안·개인정보 최소 요구

- 전송 구간과 저장 데이터 암호화
- 서명된 단기 URL 등으로 미디어 접근 통제
- 서버에서 모든 이벤트·미디어 조회 권한 재검증
- 초대 토큰 원문 비저장 및 재사용/무차별 대입 방지
- 민감 권한 변경 감사 로그
- 최소 수집 원칙과 목적별 보존 기간 고지
- 개인정보 처리방침·이용약관·신고 절차 준비

## 13. 성공 지표와 분석 계획

### 13.1 북극성 지표

**월간 공동 추억 완성 건수(Monthly Collaborative Memories)**

**[제안 정의]** 한 이벤트에 유효 미디어가 1개 이상 있고, 서로 다른 2명 이상이 기록·메모·반응 중 하나에 기여한 경우 `공동 추억 완성`으로 센다.

보조로 **1인 추억 완성 건수**를 분리해, 공동 참여가 없더라도 제품 가치가 발생하는지 관찰한다.

### 13.2 퍼널 지표

| 단계 | 지표 | 초기 목표 |
|---|---|---|
| 생성 | 가입 후 24시간 내 첫 약속 생성률 | **[제안 지표] 40% 이상** |
| 초대 | 생성된 약속 중 초대 링크 공유율 | **[제안 지표] 60% 이상** |
| 참여 | 링크 방문 대비 승인된 참여율 | **[제안 지표] 50% 이상** |
| 첫 기록 | 약속 종료 후 48시간 내 미디어 1개 이상 등록률 | **[제안 지표] 50% 이상** |
| 공동 기여 | 활성 이벤트 중 2명 이상 기여 비율 | **[제안 지표] 30% 이상** |
| 회상 | 추억 생성 후 30일 내 재열람률 | **[제안 지표] 25% 이상** |
| 탐색 | 장소/친구 기반 찾기 과업 성공률 | **[제안 지표] 80% 이상** |

위 수치는 업계 표준이나 실측값이 아니며, 소규모 베타에서 기준선을 얻은 뒤 수정한다.

### 13.3 품질·가드레일 지표

- 업로드 성공률 및 재시도 성공률
- 업로드 완료 시간의 p50/p95
- 초대 승인 전 콘텐츠 노출 사고 0건
- 잘못된 권한으로 인한 조회·삭제 사고 0건
- 신고 처리 시간과 재신고율
- 위치 권한 거부자의 핵심 과업 완료율
- 알림 차단/옵트아웃률
- 이벤트당 삭제 요청·신고 발생률

### 14.1 우선 검증 가설

| ID | 가설 | 위험도 | 검증 방법 | 성공 기준 |

### 14.2 리서치 대상

- 5~6명: 최근 3개월 내 친구 모임 또는 여행 경험자
- 사진을 자주 공유하는 사용자와 거의 공유하지 않는 사용자를 모두 포함
- iOS/Android, 위치 권한 허용/비허용 태도 다양화
- 가능하면 실제 친구 그룹 1팀 이상 포함

### 14.3 인터뷰 질문

1. 최근 친구들과 약속을 잡은 과정을 처음부터 설명해 주세요.
2. 모임이 끝난 뒤 사진을 누가, 어디에, 언제 공유했나요?
3. 받지 못했거나 찾기 어려웠던 사진이 있었나요?
4. 과거 친구 사진을 다시 찾았던 가장 최근 상황은 무엇인가요?
5. 그 사진의 장소를 다시 찾으려면 어떻게 하나요?
6. 친구들과 사진·위치를 공유할 때 걱정되는 점은 무엇인가요?
7. 모임 중 기록과 모임 후 기록 중 어떤 방식이 덜 방해되나요?

“쓸 것 같나요?” 같은 의향 질문은 보조로만 사용하고, 과거 실제 행동과 과업 관찰을 우선한다.

### 14.4 UT 과업

1. “이번 토요일 성수동 생일 모임” 약속을 생성한다.
2. 초대 링크를 공유하고, 다른 참가자가 참여를 요청한다.
3. 호스트가 참여를 승인한다.
4. 참가자가 사진 3장을 올리고 1장에 장소를 연결한다.
5. 위치 권한을 거부한 상태에서 장소를 직접 수정한다.
6. 지도에서 “지난번 부산 카페”의 기록을 찾는다.
7. 본인이 올린 사진을 삭제한다.
8. 초대 링크가 유출됐다고 가정하고 기존 링크를 폐기한다.

### 14.5 관찰·측정

- 과업 성공/부분 성공/실패
- 완료 시간, 오류, 되돌아감, 도움 요청
- 초대 승인 전 볼 수 있다고 예상한 정보
- 위치 권한 요청을 본 순간의 이해와 신뢰
- 업로드 후 기록이 어디에 나타날 것으로 예상하는지
- 시스템 사용성 척도보다 과업별 SEQ와 정성 발화를 우선

### 14.6 의사결정 기준

- H1 또는 H2가 실패하면 약속 기반 시작점과 공동 기여 구조를 재검토한다.
- H4가 실패하면 지도 기능보다 장소 없는 타임라인을 우선한다.
- H5가 실패하면 성장 기능보다 초대·승인·삭제 통제권을 먼저 개선한다.
- H6가 실패하면 지도보다 이벤트 단위 공동 앨범의 실용성에 초점을 축소한다.

## 16. 수용 기준(Acceptance Criteria)

### AC-01 약속 생성

- Given 로그인한 사용자가 홈에 있을 때
- When 제목과 날짜를 입력하고 생성하면
- Then 장소·시간·친구가 없어도 약속이 생성되고 상세 화면으로 이동한다.

### AC-02 과거 약속

- Given 사용자가 과거 날짜로 약속을 생성할 때
- When 기록이 없으면
- Then 빈 앨범 대신 `PAST_EMPTY` 상태와 사진 추가 CTA가 표시된다.

### AC-03 링크 초대 보안

- Given 비멤버가 유효한 링크를 열었을 때
- Then 제목·날짜·호스트 외 사진·정확한 장소·멤버 목록은 보이지 않는다.
- And 로그인 및 호스트 승인 전에는 콘텐츠 API 접근이 거부된다.

### AC-04 참여 승인

- Given 참여 요청이 대기 중일 때
- When 호스트가 승인하면
- Then 요청자는 활성 멤버가 되고 이벤트 콘텐츠를 볼 수 있다.

### AC-05 링크 폐기

- Given 호스트가 기존 초대 링크를 폐기했을 때
- Then 해당 링크로 새 참여 요청을 만들 수 없다.
- And 이미 승인된 멤버의 접근권한은 유지된다.

### AC-06 사진 업로드

- Given 활성 멤버가 사진을 선택했을 때
- When 장소와 메모를 입력하지 않고 업로드하면
- Then 사진은 이벤트 타임라인에 정상 표시된다.

### AC-07 부분 실패

- Given 사진 5장 중 2장 업로드가 실패했을 때
- Then 성공한 3장은 유지되고 실패한 2장만 명확히 표시되어 재시도할 수 있다.

### AC-08 위치 권한 거부

- Given 사용자가 위치 권한을 거부했을 때
- Then 약속 생성·사진 업로드·타임라인 열람이 가능하다.
- And 사용자는 장소를 수동 검색해 연결할 수 있다.

### AC-09 지도 노출

- Given 장소가 연결된 기록과 연결되지 않은 기록이 함께 있을 때
- Then 장소가 있는 기록만 지도에 표시되고 둘 다 타임라인에는 표시된다.

### AC-10 동일 장소 집계

- Given 같은 장소에 여러 이벤트 기록이 있을 때
- Then 지도는 하나의 핀 또는 클러스터에 방문 횟수를 표시하고 날짜별 기록을 열 수 있다.

### AC-11 본인 기록 삭제

- Given 사용자가 본인이 올린 기록을 삭제할 때
- Then 확인 후 모든 멤버의 이벤트 화면에서 즉시 숨겨진다.
- And 관련 보존 처리는 정책에 따른다.

### AC-12 타인 기록 통제

- Given 사용자가 타인이 올린 사진을 문제로 신고할 때
- Then 신고 사유를 제출하고 처리 상태를 확인할 수 있다.
- And 일반 멤버는 타인의 원본을 임의 삭제할 수 없다.

### AC-13 멤버 제거

- Given 호스트가 활성 멤버를 제거했을 때
- Then 제거된 사용자의 새 조회·업로드 요청은 즉시 거부된다.
- And 기존 로컬 저장·캡처는 회수할 수 없다는 정책이 적용된다.

### AC-14 호스트 탈퇴

- Given 호스트가 유일한 소유자일 때
- When 이벤트에서 나가려 하면
- Then 다른 활성 멤버에게 역할을 이전하기 전에는 완료할 수 없다.

### AC-15 취소 이벤트

- Given 호스트가 약속을 취소할 때
- Then 멤버에게 취소 상태가 표시되고 기존 기록은 자동 삭제되지 않는다.

### AC-16 접근성

- 핵심 CTA와 본문은 WCAG AA 수준의 대비를 목표로 한다.
- 모든 아이콘 버튼에는 접근 가능한 이름이 있다.
- 지도 정보는 지도만이 아니라 목록 또는 텍스트로도 접근 가능해야 한다 **[P1 구현, P0 설계]**.

### AC-17 분석·개인정보

- 분석 이벤트에 정확한 좌표, 메모 원문, 초대 토큰이 포함되지 않는다.
- 권한 변경과 신고 처리는 감사 가능한 이벤트로 기록된다.

- 업로드 요청은 멱등성을 보장해 재시도 중복을 방지
- 앱 종료·네트워크 전환 후 업로드 상태 복구 **[P1]**
- 권한 변경은 캐시보다 서버 결정을 우선

### 17.3 접근성·국제화

- 스크린리더 레이블, 동적 글자 크기, 충분한 터치 영역 고려
- 색상만으로 업로드 실패·권한 상태를 구분하지 않음
- 이벤트 시간대 저장, 날짜·시간 로컬 표시
- 한국어 우선, 텍스트 확장을 고려한 레이아웃

### 17.4 운영 가능성

- 신고 접수·콘텐츠 임시 숨김·처리 이력 관리
- 권한 사고 추적을 위한 감사 로그
- 스토리지·트랜스코딩 비용 모니터링
- 계정·이벤트·미디어 단위 삭제/내보내기 절차

| 영상 저장·전송 비용 | 중간 | P1, 길이·용량 제한, 최적화본, 비용 지표 관찰 |
| 지도 데이터 비용·정확도 | 중간 | 수동 장소, 캐시, 공급자 추상화, 목록 대안 |
| 콘텐츠 분쟁·불법물 | 높음 | 신고·임시 숨김·감사 로그·운영 정책 마련 |
| 회상 리텐션 검증에 긴 시간 필요 | 중간 | 7일 프로젝트에서는 의향이 아닌 찾기 과업, 후속 다이어리 스터디 |

## 21. 단계별 로드맵

### Phase 0 — 7일 UX 검증

- 문제 인터뷰
- P0 클릭형 프로토타입
- 핵심 과업 UT
- 프라이버시·지도 이해도 검증

### Phase 1 — 알파

- 약속 생성, 링크 승인, 사진 공동 업로드
- 수동 장소, 타임라인, 지도
- 기본 삭제·신고·멤버 관리
- 분석 이벤트와 품질 지표

### Phase 2 — 베타

- 짧은 영상
- 친구·기간 필터
- 반응·댓글
- 실패 복구·내보내기 강화
- 2~4주 리텐션 실험

### Phase 3 — 회상 강화

- N년 전 오늘
- 연간/친구별 회상
- 장소 재방문 제안
- 사용자가 통제하는 자동 분류·하이라이트 검토

각 단계는 이전 단계의 가설이 지지될 때만 확장한다.
